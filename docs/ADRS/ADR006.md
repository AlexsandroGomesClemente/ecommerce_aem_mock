# ADR-006: Testes de Carga e Stress Contínuos na Esteira (CI/CD)

Status: Aceito
Contexto:
Datas sazonais como Black Friday, Dia das Mães ou lançamentos de novos smartphones geram picos massivos de tráfego. Se uma query GraphQL ou uma consulta no PostgreSQL for ineficiente, a aplicação inteira pode cair. Precisamos garantir que os limites da aplicação (AEM e Java) sejam conhecidos e monitorados antes que o código chegue em Produção.Decisão:
Utilizar o k6 (ferramenta open-source de testes de carga focada em desenvolvedores) para criar scripts de simulação de tráfego.
Os testes simularão jornadas completas (ex: acessar home no AEM -> buscar catálogo via GraphQL -> adicionar ao carrinho) e serão integrados à pipeline de CI/CD. O deploy será bloqueado se os testes falharem nos SLOs (ex: 95% das requisições devem responder em menos de 200ms).Consequências:

Positivas: Prevenção proativa de incidentes N2/N3 em produção. Como os scripts do k6 são escritos em JavaScript, a mesma equipe que atua no Vue.js pode ajudar a criar cenários de teste complexos.

Negativas: Adiciona tempo ao tempo total de execução da pipeline (build time). Exigirá um ambiente de Staging (Pré-produção) espelhado em Docker que tenha capacidade computacional suficiente para aguentar o teste de carga sem falsear os resultados.
